## 2. 阻塞问题

### [P1] 无效恢复日志会中止整个候选扫描（确定问题）

- 位置：`src/Cap.Recording/RecordingRecovery.cs:32`，关联 `:127`、`:129`、`:133`。
- 问题：`FrameJournal.Open` 对无效签名、头长度或维度抛出 `InvalidDataException`，但逐文件扫描仅捕获 `IOException`、`JsonException` 和 `ArgumentException`。`InvalidDataException` 继承 `SystemException`，不属于 `IOException`；本次通过 `[System.IO.InvalidDataException].BaseType.FullName` 实际确认了这一点。
- 复现：保存目录内同时放一份正常 `.capjournal` 和一份零字节或签名错误的 `.capjournal`，调用 `FindCandidates`。扫描到坏文件便抛出异常，正常候选列表也不能返回。
- 影响：一次未完成的日志初始化或损坏文件就能阻止用户发现同目录中其他可恢复录制，与失败可恢复的要求冲突。
- 建议：逐文件显式捕获 `InvalidDataException` 并记录该文件的原因后继续扫描；同时考虑该文件不可读时的 `UnauthorizedAccessException`。补充“一个坏日志与一个正常日志共存”的回归场景。

### [P1] 窗口关闭绕过最后一帧及正常发布（确定问题，主任务正在修复）

- 位置：审阅时 `src/Cap.Recording/RecordingSession.cs:118`、`:125`、`:137`–`:150`、`:156`–`:160`。
- 问题：关闭所选窗口会让捕获源抛出异常，直接进入外层失败处理；循环内的 `pending` 不会走最后一次 `WriteFrame`，正常发布也被跳过。
- 复现：开始指定窗口录制，在首帧进度出现后、下一帧写入前关闭目标窗口。首帧仅存于 `pending`，日志中没有已提交帧；若关闭较晚，则仍进入 Failed 并要求用户另行恢复。
- 影响：短录制可能没有可恢复画面；普通窗口关闭也显示录制失败，和界面“窗口关闭时结束并保留已录画面”的行为说明不符。
- 建议：将已录过有效帧后的 `CaptureTargetClosedException` 作为正常结束条件，停止活动时钟、写出 pending，再完成编码和发布；在尚无任何帧时明确报告无法开始，避免再去已关闭的源补抓首帧。暂停期间关闭窗口也应明确何时检测。Capture 已根据主任务指令提供类型化异常并将其排除在 WGC 通用回退之外。
- 状态：以上描述为修复前观察；Recording 实现者已接手正常收尾及对应回归。

## 3. 建议修改

### [P2] 恢复取消/失败留下固定临时文件，阻止同目标重试（确定问题）

- 位置：`src/Cap.Recording/RecordingRecovery.cs:53`–`:66`；`src/Cap.Recording/GifEncoder.cs:32`；`src/Cap.Recording/MfVideoEncoder.cs:22`。
- 问题：恢复始终使用 `outputPath + ".recovering." + ext`，但取消、无完整帧、损坏中间帧或编码失败后没有清理/隔离该临时文件。GIF 使用 `CreateNew`，MP4 也拒绝已存在文件。
- 复现：在至少一帧已写入后取消 `RecoverAsync`，然后用相同 `journalPath` 与 `outputPath` 重试。最终输出不存在，但旧 `.recovering.ext` 已存在，第二次启动编码失败。
- 影响：取消不能自然重试；失败原因被新的文件冲突掩盖，用户需要手动清理或换名。
- 建议：使用每次恢复唯一的同目录临时文件；失败时保留源 journal，并明确清理自己的临时文件或返回其保留位置。不要覆盖未知的旧恢复文件。补充取消后重试测试。

### [P2] 覆盖截图保存失败时会破坏原文件（确定问题）

- 位置：`src/Cap.Annotation/ScreenshotWindow.cs:332`。
- 问题：用户确认覆盖后，`FileMode.Create` 在编码完成前就截断目标文件；保存中途磁盘耗尽或编码器报错只弹出失败提示，原图片已丢失。
- 复现：选择已存在的 PNG/JPEG 并确认覆盖，在保存中途触发写入失败。原文件成为空文件或不完整图片。
- 影响：失败保存同时破坏此前的有效图片；保留当前编辑状态无法恢复旧文件。
- 建议：先在目标目录编码到唯一临时文件，成功关闭后再替换目标；失败保留原文件并移除本次临时文件。覆盖确认保持现有交互即可。

## 6. 风险总结

确定的主要风险集中在关闭/恢复/写入失败的处理链，常规编辑像素路径未发现明确错误。MF sample/buffer 的正常及异常释放都有 `finally`，cursor 图标位图和 Graphics HDC 同样有释放；GIF 只保留当前与上一索引帧、字典及有限输出块，没有随录制时长增长的帧列表。

尚未验证的风险包括磁盘突然耗尽、MF 编码设备/系统组件失败、异常热插拔、混合 DPI 和数小时录制。构造函数中发生磁盘写入失败后的文件句柄即时释放、低级鼠标钩子线程停止超时也未做故障注入；没有足够运行证据将其断言为已发生泄漏。
