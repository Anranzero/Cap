# cap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Track checkable steps below.

**Goal:** Produce a real portable Windows screenshot/editor and MP4/GIF recorder in dist/cap.exe.

**Architecture:** Small independent assemblies with Core contracts. Native Windows capture and encoders; WPF floating windows; tray resident app without a startup main window.

**Tech Stack:** C#, .NET 8, WPF, Win32, WGC, Media Foundation.

**Spec:** ../specs/2026-10-24-cap-design.md and full user request.

## Global Constraints
- Windows 10/11 x64, .NET 8 WPF; executable named cap.exe.
- Fully free, offline, no ads/membership, self-contained single-file.
- No new third-party production dependencies; no browser verification.
- Physical-pixel desktop coordinates, negative origins, mixed DPI.
- Source files below 1000 lines; minimal focused edits and actual build evidence.

## Review Focus
- Invalid/empty/offscreen selections must not corrupt memory or crash.
- Pause/stop/failure races must preserve recording state and release native resources.
- Disk-full/permission errors must keep recoverable data and explain failure.
- Mixed-DPI monitors must preserve screenshot resolution and coordinates.
- Encoding and preview must work from the published executable without development files.

## Tasks
- [x] 1. Scaffold modules and install local SDK; build baseline.
- [x] 2. Capture: monitors/windows, WGC backend, GDI fallback and physical region source.
- [x] 3. Annotation: frozen selection/move/resize/snap, drawing tools, pixel filters, history, clipboard/save/pin.
- [x] 4. Recording: system MP4 and streaming GIF, frame pacing, pause/resume, pixel overlays, recovery.
- [x] 5. System/App: tray, hotkeys, persistent settings/autostart, recording setup/control/preview and themes.
- [x] 6. Tests and independent review; fix real failures; README/build script/license.
- [x] 7. Release publish, launch copied single EXE, record hashes/size and verification limitations.

Final evidence: ../../verification.md. The user-supplied directory was empty; development stayed in that directory on develop/cap. No remote was created or pushed. Native hardware and endurance coverage limits are documented, not assumed passed. Packaging defaults to no assembly compression after a measured reduction in idle private memory; build.ps1 -Compact retains the smaller-file option.
