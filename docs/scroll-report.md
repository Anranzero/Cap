# 滚动截图实现与验证

## 修改范围

- `src/Cap.Annotation/ScrollingCaptureWorkflow.cs`：固定物理区域的真实 GDI 截图、小型浮动控制条、手动捕获、可选停稳自动捕获、撤销、完成和取消。
- `src/Cap.Annotation/ScrollingCaptureStitcher.cs`：独立的纵向重叠匹配和追加缓冲区实现，不引入生产依赖。
- `tests/Cap.Scroll.Tests/`：合成像素断言及可选 Windows 原生截图集成验证。

入口为 `ScrollingCaptureWorkflow.RunAsync(PixelRect region, string saveDirectory, bool darkTheme = false)`。完成返回冻结的 96 DPI BGRA32 `BitmapSource`，取消返回 `null`。输出的预览、复制和保存由调用方的结果窗口负责。

## 实际行为

首屏在控制条创建前捕获并完整保留。用户自行向下滚动目标内容，每次保留至少约三分之一的上屏内容，再点击“捕获下一屏”。可选择每 400ms 采样、连续两次画面稳定后自动尝试拼接；程序不会发送滚轮或其他用户应用输入。

控制条必须成功通过 `ExcludeWindow` 排除后才能捕获下一屏；排除失败时停止后续捕获并提示。控制条按显示器物理工作区摆放，尽量避开选区，支持拖动。关闭、取消、完成都会停止定时器。

拼接扫描向下偏移，使用跨宽度亮度采样找出唯一、足够接近的重叠，并以更密集的采样复核。相同画面不追加，反向滚动、重复纹理、重叠不足、固定底栏或无法确认的匹配均保留原结果并提示。匹配包含上一屏的末行，避免空白固定底栏成为错误接缝。顶部约 10% 不参与匹配，以允许小型固定标题栏；首屏仍完整保留。

只保存首屏、每次追加的像素条带及上一屏，不保存无界全帧历史。撤销删除末条带，并从保留内容重建上一屏。默认上限为 **4000 万像素、30000 像素高**；达到上限后只能完成或撤销。4000 万像素约为 160MB 原始输出，最终构造连续缓冲区与 WPF 位图时会有额外内存占用。

## 尚未验证及已知限制

- 没有对任意第三方应用逐一人工滚动验证；复杂动画、懒加载、重排、缩放、横向移动、稀疏或重复内容可能无法建立可靠匹配。
- 选择内容区域时应避开大固定标题栏、固定侧栏和底栏。无法可靠匹配时停止追加，不会猜测拼接。
- 匹配使用抽样而不是逐像素穷举，不能保证任意对抗性或高度重复图案均被识别。
- 原生集成验证覆盖当前桌面与 DPI；尚未逐一覆盖所有多显示器、混合 DPI、远程桌面和受保护内容组合。
