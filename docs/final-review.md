## 2. 阻塞问题

当前未发现未处理的阻塞问题。

### 已解决：[P1] 自动完成没有驱动 App 清理会话与打开预览

- 位置：`src/Cap.App/App.xaml.cs:95`，关联 `src/Cap.Recording/RecordingSession.cs:120`、`:157`，对应发现时实际工作文件。
- 问题：RecordingSession 已将有首帧后的窗口关闭处理为正常结束，但 App 只监听 Progress 和 Failed，没有观察 Completion 的成功完成。窗口关闭后文件可正常生成，但控制条与托盘仍显示正在录制，session 字段没有释放。
- 影响：用户看不到自动结束/预览；下一次录制快捷键只清理旧会话，不能直接启动新录制。
- 复现：录制指定窗口，等待至少一帧，关闭该窗口，然后查看控制条/托盘并再次按录制快捷键。
- 建议：统一观察每个 recording.Completion，在 UI 线程检查会话身份后调用共享 StopRecordingAsync，成功与失败都走同一清理路径，保留现有 stopTask 去重。
- 确定性：由当前成功完成控制流与 App 订阅关系确认；没有执行 UI 时序自动化复现。
- 最新复核：`App.xaml.cs:103` 已启动 `ObserveCompletionAsync`，`:106` 起统一观察成功/失败，核对会话身份后等待共享停止任务。该控制流已修复，最终构建及端到端 UI 结果由主任务记录。

## 3. 建议修改

当前未发现未处理的确定建议项。以下保留已解决问题的审阅记录。

### 已解决：[P2] 暂停中的目标关闭不会被自动发现

- 位置：`src/Cap.Recording/RecordingSession.cs:110`。
- 问题：Paused 分支无限等待 changed；目标关闭只在 source.Capture 时抛出类型化异常。暂停后关闭目标，不会触发 changed，也不会进入 Capture。
- 影响：会话一直保持 Paused，直到用户手动继续或停止；与界面“窗口关闭时结束并保留已录画面”的描述不一致。已有 pending 帧的手动停止仍能保存，不据此宣称数据丢失。
- 建议：暂停时通过有界等待及目标存活检查识别关闭，不采样也不增加暂停时间；或者明确记录只在继续/停止时发现关闭的限制。优先用前者统一行为。
- 验证建议：开始窗口录制并得到首帧 → Pause → 关闭目标 → 等待 Completion，断言正常完成且文件可解码、暂停时长未加入输出。
- 最新复核：Paused 分支已对窗口目标每 250 ms 检查 IsWindow；区域目标仍使用事件等待，没有继续采样暂停帧。已有首帧时会进入正常最终编码路径。

### 已解决：[P2] 关闭目标时读取 Bounds 绕过正常结束

- 位置：`src/Cap.Recording/RecordingSession.cs:128`，关联 `src/Cap.Capture/GraphicsCaptureSource.cs:29`。
- 问题：类型化关闭异常的 catch 只包住 source.Capture；紧接着的 source.Bounds 位于 catch 外。窗口在这两次读取之间关闭时，Bounds 中的 GetWindowBounds 也会抛 CaptureTargetClosedException，直接进入 Failed，跳过 pending 的正常发布。
- 影响：大多数关闭正常，但这一线程交错仍会显示失败并要求手动恢复，最后 pending 可能未写入。
- 建议：将 source.Bounds 与 source.Capture 一起放入同一个 try，取得 PixelRect 局部值后再 Process，保持现有有 pending 才正常结束的条件。
- 确定性：代码中存在这条精确异常路径；未运行线程时序故障注入，不声称在本机实际触发。
- 最新复核：`:125` 起已将 Capture 与 Bounds 读取放在同一类型化异常处理内，Process 使用已取得的 capturedBounds。源码中的这条异常遗漏已消除。

### 已在本轮工作区复核的修复

- WGC 已将缓存存在时的 100 ms 等待移除，仅首帧等待 1500 ms。静态窗口不再在代码路径上将独立鼠标叠加限制为约 10 Hz；真实帧率仍取决于处理与编码速度。
- App 已为进度/失败回调增加会话身份检查；异步停止共享同一个 Task；恢复退出会取消并等待 recoveryTask；跨目录恢复读取实际日志格式；截图取消恢复先前可见的设置窗口。
- 无效恢复日志逐文件捕获 InvalidDataException/UnauthorizedAccessException；恢复临时文件采用唯一名称并在失败时清理；原日志保留。
- ScreenshotExport 先完成同目录临时编码再替换目标，避免失败前截断已有图片。现有测试包含锁定目标替换失败后原始字节不变。
- CursorRenderer 的临时 Console.WriteLine 已从实际文件移除。

以上为代码阅读复核，不替代主任务最后构建与专项回归结果。
